# Версии проекта

Откройте **Модули → Каталог → Версии проекта → Добавить**. В проекте появится вкладка **Версии**. Модуль подключается отдельно для каждого проекта и по умолчанию выключен. Отключение скрывает вкладку и запрещает новые записи и правки; уже сохранённая история остаётся в базе и экспорте.

## Записать выпуск

Нажмите «Добавить версию» и заполните номер или другое имя версии, окружение, изменения и комментарий к записи. Можно добавить название выпуска, дату, commit/tag и ссылку. Поддерживаются собственные имена окружений; обычное значение — `production`.

- **Черновик** — выпуск ещё готовится; дата необязательна.
- **Выпущена** — вы отмечаете состоявшийся выпуск; дата обязательна.
- **Откачена** — вы отмечаете откат ранее выпущенной версии; дата её выпуска остаётся обязательной. Причину отката запишите в изменениях и комментарии к правке.

Номер версии — пользовательское имя, например `2.4.0` или `2026.10`. Это не внутренний счётчик редакций записи. Повторное размещение одной версии в нескольких окружениях можно записывать отдельно. DashAI сохраняет сообщение человека или агента о выпуске; приложение не выполняет deploy и не подтверждает доступность production.

Журнал показывает историю по датам, поддерживает поиск по имени, названию, изменениям и окружению, фильтр состояния и страницы по 30 записей. Откройте запись, чтобы прочитать полный текст или исправить её. Исправление сохраняет автора, причину и значения «было → стало» в общей истории проекта. При конфликте черновик остаётся на экране; перечитайте актуальную запись перед новой правкой.

## Общий API и MCP

- `GET /api/projects/{project_id}/releases?q=&status=&environment=&offset=0&limit=30` — ограниченные summaries, `total` и `has_more`. Максимум 100 записей на запрос, preview изменений до 300 символов.
- `GET /api/projects/{project_id}/releases/{release_id}` — полная запись.
- `POST /api/projects/{project_id}/releases` — `{version_name, changelog, title?, status?, environment?, released_at?, link?, source_revision?, reason, idempotency_key?}`.
- `PATCH /api/projects/{project_id}/releases/{release_id}` — `{expected_version, changes, reason, idempotency_key?}`.
- MCP: `list_project_releases`, `get_project_release`, `create_project_release`, `update_project_release`. Перед правкой прочитайте текущую версию; при сетевом повторе сохраните тот же idempotency key и payload. Для включения модуля используйте существующий `configure_project_module` с `module_id="releases"`.

Дата имеет календарный формат `YYYY-MM-DD`; ссылка — HTTP(S) без встроенных credentials. Максимальные размеры: имя версии и окружение — по 100 символов, название — 200, изменения — 50 000, ссылка — 2 000, commit/tag — 200. Полные изменения не передаются в обычном polling доски: list использует preview, а history, detail и project export сохраняют полный текст.

Запись, audit event и idempotency сохраняются одной транзакцией общей SQLite. У модуля нет отдельного project store. Версии не отправляются в Confluence/Jira автоматически; текущие интеграции публикуют архитектурные знания и документные модули.

## Свои исполнители

При создании или редактировании задачи нажмите **Свой исполнитель**, введите имя человека, команды, роли или модели и нажмите **Сохранить исполнителя**. Новый исполнитель сразу выбирается в задаче и становится доступен во всех проектах этого пространства, в том числе после перезапуска. Повторное имя из текущего списка выбирает существующего исполнителя.

Такое добавление не выдаёт MCP-токен и не означает подключение модели. Для отдельного MCP-клиента создайте идентичность с credentials в разделе «Коннекторы». Существующие идентичности также можно выбирать исполнителями задач.
