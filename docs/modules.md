# Модули проекта

Откройте проект → **Модули**. Во вкладке «В проекте» видны включённые возможности; «Каталог» показывает доступные дополнения. Кнопка «Добавить» включает модуль только для этого проекта, «Убрать» скрывает его без удаления данных. Доска и история — постоянная основа пространства.

## Встроенные возможности

Карта проекта, архитектура и документация включены по умолчанию, в том числе для старых баз. Confluence/Jira выключены до явного включения. Включённый модуль появляется среди вкладок проекта. Отключение интеграций останавливает постановку и отправку новых запросов; запрос, уже принятый внешним сервером, отозвать нельзя.

## Документные модули

«Архитектурные решения», «Риски и ограничения», «Запуск и эксплуатация» дают стартовую структуру, которую можно заполнить обычным текстом или Markdown. Выберите документ, отредактируйте текст и комментарий к правке, сохраните. Отключите и включите снова — сохранённый текст останется.

«Свой модуль» создаёт именованный повторно используемый шаблон, например чек-лист выпуска или требования к API. Шаблон становится доступен в каталоге, но не включается во всех проектах автоматически. Каждый проект заполняет собственную копию; изменение текста одного проекта не меняет соседние проекты. Пользовательский модуль — документ, он не исполняет Python/JavaScript и не устанавливает зависимости.

Несохранённый текст защищён при смене проекта, вкладки и закрытии страницы. При конфликте версий сохранение останавливается: перечитайте состояние и подтвердите правку снова. Экспорт проекта включает состояние модулей и их текст. Включённые документные модули также доступны для публикации через интеграции.

## Общий API и MCP

- `GET /api/modules` — каталог; `POST /api/modules` — новый шаблон `{name, description?, template?, reason, idempotency_key?}`.
- `GET /api/projects/{id}/modules` — состояние проекта и документы.
- `PUT /api/projects/{id}/modules/{module_id}` — `{expected_version, enabled, content?, reason, idempotency_key?}`. Пропущенный `content` сохраняет текст; `""` явно очищает. Начальная версия не настроенного модуля — 0.
- MCP: `list_modules`, `get_project_modules`, `create_module_template`, `configure_project_module`. Списки ограничены и поддерживают пагинацию; один полный документ запрашивается через `module_id`.

Запись модуля и audit event атомарны; постановка включённых интеграций выполняется в той же транзакции. Модули сохраняются в общей SQLite, без дополнительного project store. Доступность вкладки — настройка интерфейса, не граница авторизации локального API.

## Добавление новой встроенной возможности разработчиком

Добавьте конкретный модуль в `server/modules.py:BUILTINS`, его UI в существующее пространство проекта и domain-операции в общий HTTP API. Внешние агенты должны пользоваться тем же domain behavior через MCP. Храните данные и аудит совместно, сохраняйте их при выключении, проверяйте выключение фоновых побочных действий. Новая возможность требует реального сценария; общий runtime сторонних плагинов пока не нужен. Основания выбора — [исследование](research/07-project-modularity.md).
