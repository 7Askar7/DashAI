# Независимая проверка Kanban 1.2

Reviewer: отдельный агент `desktop_critic`. Проверены новая `KanbanBoard`, диалог переноса, фильтры, сохранение истории, desktop/mobile UI и пользовательская документация. Прочитаны architecture, исследования и оба Ponytail skill. Проверка использует временную SQLite-базу и настоящий сервер; рабочее пространство пользователя и установленное приложение не затрагиваются.

## Найденные проблемы

1. Первоначальные колонки по 280 px требовали горизонтальной прокрутки при 1440 px. После уменьшения минимальной ширины до 214 px все пять колонок помещаются: `clientWidth = scrollWidth = 1138`. Названия статусов, карточки и действия читаются; длинные метки разделов сокращаются с доступным полным `title`.
2. Фильтр статуса из списка мог скрывать остальные статусы Kanban, включая выбранную мобильную колонку. Исправлено: он применяется только в списке. Реальный переключатель список → доска после выбора `done` снова показывает все восемь задач и пять колонок; фильтр раздела сохраняет общий вид по статусам.
3. Успешный перенос удалял исходный select; возврат фокуса native dialog обращался к уже отсоединенному элементу. Реальная клавиатурная проверка обнаружила `document.activeElement === BODY`. Однократный `requestAnimationFrame` не решил проблему и повторно провалил regression. Исправлено восстановлением фокуса после React commit через pending ref и effect: на desktop фокус получает select новой карточки, на mobile — кнопка выбранного видимого статуса. Оба сценария подтверждены retained assert.

## Воспроизводимая проверка

```powershell
npm run build
node scripts/python.mjs scripts/kanban_smoke.py
```

Используется уже установленный Playwright и Chromium; при необходимости путь браузера задается `AGENTBOARD_BROWSER`. Тест создает один проект, два раздела и восемь карточек разных статусов. Сетевая граница задерживается только для конкурентного PATCH и потери ответа; ответы и мутации выполняет настоящий API.

Проверяемые сценарии:

- По умолчанию отдельные колонки статусов всего проекта; каждая карточка встречается ровно один раз. Задачи разных разделов объединены по статусу, разделы остаются метками.
- Фильтр раздела и переключение список → доска не оставляют скрытый фильтр статуса.
- Причина обязательна; отмена и Escape не изменяют карточку и не добавляют событие.
- Переход в «Готово» без evidence отвергается общей серверной проверкой; успешного audit event нет.
- Native drag открывает подтверждение; только после причины создается одно событие с автором и статусами «было → стало». История видна в задаче и сохраняется после reload.
- Потеря настоящего успешного ответа и повтор с тем же idempotency key не дублируют историю.
- Escape во время сохранения оставляет диалог; настоящий stale PATCH сохраняет причину, требует обновления и повторного подтверждения, не перезаписывает конкурентные поля.
- Native select и подтверждение доступны с клавиатуры; проверяется восстановление фокуса.
- На 390/320 px кнопки статусов показывают одну выбранную колонку, имеют `aria-pressed`; поле переноса имеет высоту не меньше 44 px. Нет горизонтального переполнения страницы; мобильный перенос сохраняет причину и историю.

Артефакты: `artifacts/qa/kanban-results.json`, `kanban-desktop.png`, `kanban-mobile-390.png`, `kanban-mobile-320.png`. Desktop имеет 1138 px рабочей ширины; мобильные доски 354 и 284 px. Playwright проверяет отсутствие необработанных ошибок страницы. Скриншоты просмотрены независимо.

Итоговый production build `index-CM5xKQTw.js` / `index-9LvY9Z7e.css`: **9 групп интеграционных проверок PASS**, включая потерю настоящего ответа, конкурентную правку и восстановление desktop/mobile фокуса. `py_compile` и `git diff --check` прошли. Открытых correctness замечаний по проверенному scope нет.
