# UX-аудит и проверка реализации — 18.10.2026

## Результат

Улучшен ежедневный цикл «найти задачу → понять результат → проверить → продолжить». Основание — [исследование потребностей](../research/08-user-needs-ux-audit.md), чтение актуального контракта и кода, исходные снимки интерфейса и отдельный аудит логики. Это кабинетное исследование и инженерная проверка; интервью, пользовательская аналитика и измерение роста удобства не проводились.

| Область | Изменение и причина |
| --- | --- |
| Выбор следующего действия | Быстрые выборки всех задач, работы, проверки, блокировок и неназначенных задач вместо статичных счётчиков. Дополнительные фильтры раскрываются по запросу; выбранные значения и количество результатов остаются видны. |
| Последовательность поиска | Доска и список сохраняют одинаковое множество результатов. Поиск обрезает внешние пробелы, включает критерии; на мобильном открывает колонку с совпадением. Новая задача наследует выбранный подпроект, после создания сбрасывает фильтры и открывает подробности. |
| Проверка результата | В начале подробностей показаны наличие критериев, незавершённые зависимости и последнее evidence с автором/временем. Полный текст доступен с возвратом фокуса на запись. Интерфейс явно сообщает, что проверку описывает автор. |
| Защита работы | Закрытие, Escape, backdrop, отмена редактирования и уход со страницы учитывают фактические изменения. Пока запрос выполняется, поля и закрытие заблокированы. Смена типа заметки защищает дополнительные поля правки кода. Ошибка сохранения сохраняет ввод. |
| История | Новый необязательный `order=desc&before=…` открывает последние события и подгружает старые. Прежний MCP/delta-контракт `after` сохранён. Поиск честно обозначен как поиск по загруженной части. Проектная история имеет своё действие обновления. |
| Визуальная иерархия | Компактная шапка, спокойнее границы колонок, более читаемые фильтры, горизонтальные группы действий на узком экране, первый шаг вместо пяти пустых колонок. Убраны номера версий записей из основного просмотра и общие аватары, похожие на участников проекта. |
| Доступность и правдивость | Текущая навигация обозначена `aria-current`, фильтры — `aria-pressed`/`aria-expanded`. Сохранены native select и перемещение без drag. После перемещения из фильтра фокус возвращается на видимую выборку. Ошибка отдельного действия не объявляет сервер отключённым; время обновления обозначено как время доски. |

## Изменённые в этой итерации файлы

- `src/App.tsx`, `src/styles.css`, `src/KanbanBoard.tsx`, `src/kanban.css`, новый `src/task-review.css`.
- `server/app.py`, `tests/test_api.py`: только расширение чтения истории и его regression относительно исходного состояния этой итерации.
- `scripts/ux_board_smoke.py`, `scripts/task_draft_smoke.py`; `scripts/ui_smoke.py` адаптирован к новому пустому состоянию и явному подтверждению намеренного отказа от черновика.
- `README.md`, `docs/architecture.md`, исследование и этот отчёт.

Рабочее дерево содержало существенные изменения до начала аудита. Они сохранены; полный `git diff` относительно HEAD шире указанной итерации. Новые runtime-зависимости, запуск моделей, отдельный store, публикация и изменения пользовательской базы не добавлялись.

## Границы и следующий шаг

MCP `agentboard.list_projects` вернул **HTTP 401: неверный токен агента**. Поэтому карточки, claim, log_change и переходы review/done в реальной доске не выполнялись; локальные credentials не читались и ошибка авторизации не обходилась.

Следующие кандидаты — ссылки на задачи, восстановление вида/фильтров, смысловые фильтры истории и архив с восстановлением. Приоритет следует проверить интервью и сценариями из исследования. Поиск истории сейчас ограничен загруженными событиями; это подписано в UI. Установленный VSIX, native desktop-пакет и внешние сервисы в этом аудите не пересобирались и не проверялись как deployment.
