# Документация: аудит чтения

Дата: 18.10.2026. Область: интерфейс документации DashAI, без изменения опубликованных материалов проверяемого проекта.

## Наблюдение и решение

В существующем локальном проекте просмотрены документация и состав большого снимка с файлами, папками и опубликованными схемами. Старый просмотр одновременно раскрывал все файлы, постоянно показывал настройки, повторял длинные сведения о снимке и не имел навигации по разделам. Это наблюдение одного существующего проекта, не пользовательское интервью.

Чтение теперь отделено от настройки: оглавление на широком экране, закреплённый native select на узком; файл раскрывается по запросу, поиск работает по пути и объяснению, страницы ограничены 30 строками. У пустого архитектурного раздела есть объяснение и переход к выбору схем. Ширина текста ограничена для чтения; большие описания проекта и снимка раскрываются отдельно. Опубликованный состав не изменялся автоматически.

Настройки сохраняют прежний version/reason/idempotency путь. Сохранение и экспорт блокируют уход во время операции; несохранённое название/контекст сохраняются при чтении других разделов. HTML/PDF готовят схемы сами, используют полный состав и целые SVG. Markdown модулей, контекста и описаний проходит общий безопасный renderer. DOMPurify и Marked закреплены напрямую на уже установленных версиях, без добавления другого parser/runtime.

## Границы

Проверка печати снимает полное печатное DOM-представление и проверяет print CSS; системный диалог/физический принтер автоматический тест не открывает. Проверки на узких экранах выполнены в Chromium, не на физическом телефоне. VS Code smoke адаптирован к новой навигации; новый VSIX в этой итерации не собирался, нативный host повторно не прогонялся.

Fragment-ссылки и относительные пути в Markdown остаются текстом до появления разрешения путей внутри документа. Изображения заменены alt-текстом. Это исключает фоновые внешние загрузки и изменения task-history от произвольных ссылок документа.

MCP agentboard вернул HTTP 401 (invalid agent token), поэтому карточка/журнал изменений через него в этой итерации не создавались. Токены из файлов не извлекались; просмотр выполнен через доступный локальный интерфейс.
