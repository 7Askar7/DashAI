## Реализация и границы

Модуль `releases` по умолчанию выключен. `server/releases.py` использует общую SQLite и `Store.write/record`: создание и исправление записи, audit и idempotency атомарны. UI и четыре MCP-инструмента используют один HTTP-контракт. Отключение запрещает новые записи и правки, но сохраняет чтение и экспорт истории. Номер версии — имя пользователя, внутренний `version` — счётчик редакций для optimistic locking. Текст changelog ограничен 50 000 символами; списки и polling возвращают сокращённый материал до Python-декодирования. Дата календарная, состояние выпуска задаёт автор. Реальный deploy и автоматическая отправка релизов в Atlassian не выполняются.

`AssigneeSelect` в формах создания и редактирования задачи сохраняет обычную идентичность в существующем глобальном каталоге `agents` с `issue_token=false`. Token/hash не создаются; конфигурация credentials не меняется. Клиент выбирает имеющееся имя вместо повторного создания, новый исполнитель сразу выбран. Обычная выдача токена в коннекторах сохраняет прежний human-only контракт. Поля блокируются при записи исполнителя и родительской задачи; native form validation препятствует сохранению задачи с незавершённым вводом нового исполнителя.

При несовпадении версий сервера и расширения VS Code показывает фактические номера в постоянном status bar и warning. Активный MCP по-прежнему запрещает остановку runtime; старые процессы не завершаются принудительно. Это закрывает проблему исчезающего уведомления после обновления: установленная версия больше не воспринимается как версия реально запущенного сервера.
