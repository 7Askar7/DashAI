# Независимая UX-проверка

Дата плана: 3 октября 2026 года. Основание: [UX/UI исследование](../research/03-ux-ui.md) и [контракт реализации](../architecture.md). Этот файл содержит план, а не утверждение о пройденных тестах. Итог фактической проверки, screenshots, дефекты и перепроверки сохраняются отдельно в `ux-review.md`.

## Порядок проверки

Проверять работающий локальный продукт. Начать с пустого рабочего пространства либо явно названного тестового проекта, чтобы визуальные данные нельзя было принять за реальную выполненную работу. Фиксировать только наблюдавшиеся результаты. Отделять проверки API/автотестов от сценария, выполненного человеком через UI.

Для каждого дефекта указывать viewport, исходное состояние, точные шаги, ожидаемый и фактический результат. P0 — потеря данных/невозможность работы; P1 — главный сценарий или accessibility заблокированы; P2 — восстановимая проблема иерархии, текста или поведения; P3 — визуальная полировка. Исправленный дефект перепроверяется теми же шагами; «прочитал новый код» не является UI-перепроверкой.

## Клавиатура и доступность

| ID | Проверка | Критерий |
| --- | --- | --- |
| A11Y-01 | Tab/Shift+Tab от navigation через основные действия | Порядок соответствует чтению; focus всегда виден |
| A11Y-02 | Открыть/закрыть modal клавиатурой | Focus попадает внутрь, Tab замкнут, Escape и visible close работают, focus возвращается |
| A11Y-03 | Navigation tabs | Нативные controls либо полный APG tab pattern без ложных ARIA roles |
| A11Y-04 | Icon buttons и inputs | Accessible names и labels существуют, placeholder не единственная подпись |
| A11Y-05 | Статусы и авторы без различения цвета | Текст объясняет значение; цвет supplementary |
| A11Y-06 | Успех/ошибка сохранения | Assistive technology может узнать результат без неожиданного focus stealing |
| A11Y-07 | CSS computed colors | Contrast основного текста ≥4.5:1, большого ≥3:1, необходимых UI контуров ≥3:1 |
| A11Y-08 | Targets и spacing | Минимум 24×24 CSS px или допустимое исключение; ключевые controls крупнее |
| A11Y-09 | Browser zoom / reduced motion | Нет потерянных controls; unnecessary animation отключается |
| A11Y-10 | Sticky header / открытая панель | Focused control не спрятан под authored overlay |

Автоматический accessibility scanner помогает находить ошибки, но его успешный результат не заменяет keyboard сценарий, screen reader или визуальную проверку.

## Screenshots и стресс-контент

Минимальные screenshots: desktop 1440×1000 — доска с двумя секциями, открытые подробности, история и connectors; mobile 390×844 — navigation, доска/список, форма и details; narrow 320 px — форма и история. Дополнительно проверить 1280 px и zoom 200–400% при оценке reflow.

Стресс-контент: русское название проекта 80 символов, заголовок задачи 160 символов, длинный Windows path с пробелами, rationale на 3 абзаца, 30+ событий, пустые optional поля, неназначенный исполнитель, blocked task, несколько одинаковых коротких заголовков с разными ID. Проверить wrapping, accessible full text, устойчивость layout и отсутствие вложенных scroll traps.

Критерий визуальной приёмки: пользователь видит рабочую структуру проекта, следующий шаг и требуемое внимание; кнопки и лента не конкурируют с главным содержимым; слова имеют достаточный контраст; интервалы и типографика последовательны; все заявленные действия работают. Один красивый screenshot не доказывает эти условия.
