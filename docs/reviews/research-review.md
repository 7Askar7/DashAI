# Независимый cross review исследований

Дата: 3 октября 2026 года. Рецензент: отдельный агент UX, не автор исследований аналогов и потребностей coding agents. Проверены полные тексты [01-products.md](../research/01-products.md), [02-agent-needs.md](../research/02-agent-needs.md) и [architecture.md](../architecture.md). Собственное [UX/UI исследование](../research/03-ux-ui.md) использовано как дополнительная спецификация, а не объявлено независимо рецензированным этим же автором.

## Заключение

Исследования достаточны для начала реализации указанного локального продукта. Требование минимум 30 источников в каждом из первых двух исследований соблюдено. Выводы содержат конкретные механизмы, обязательные поля и сценарии проверки. Они не доказывают производительность, удобство или рыночную востребованность нашей реализации; документы прямо обозначают эти пределы.

Найдены и исправлены неточные границы между исследовательской рекомендацией и первоначальным контрактом. Код не изменялся. Следующая проверка — реализованные API/MCP и работающий UI; этот review не является подтверждением их готовности.

## Согласованность принятых решений

Три уровня и независимые status/section согласованы во всех документах. Общий сервер и единственная SQLite, автоматическое audit event в транзакции, authenticated actor, обязательный reason, optimistic version, atomic claim, dependencies, idempotency и MCP transport имеют понятную цель и тестируемый контракт. Браузер и агентные клиенты не получают разных бизнес-правил.

История задачи сохраняет объявленное краткое обоснование; она не обещает скрытые рассуждения модели и не создаёт фиктивное автоматическое наблюдение за всеми файлами. `log_change` — явный рассказ агента о правке с артефактами. Evidence и reviewer должны показываться с достаточной атрибуцией. Архитектура корректно ограничивает trust boundary одним локальным пользователем ОС.

Ponytail присутствует как реальный skill/process разработки с конкретным upstream commit; отчёты не считают его benchmark claims гарантией качества. Встроенный model runtime, canvas, RAG и отдельный executor не следуют из исходного задания и не добавлены в обязательный scope.

## Что должно быть подтверждено следующим review

1. Настоящие initialize/list_tools/call_tool по STDIO с обоими agent credentials; отдельно указать, был ли сделан authenticated test через установленный Codex/Claude Code или только protocol client.
2. Конкурирующие claim и stale update, idempotency после retry, restart persistence, ошибочные dependencies, отсутствие успешного события после failed mutation.
3. UI позволяет создать весь project→section→task workflow, читать what/why/actor/time/before-after/evidence и восстанавливать контекст после reload.
4. UI не смешивает наличие конфига, последний запрос и live session. Gate завершения объясняет недостающие criteria/evidence и не называет self-reported запись независимой проверкой.
5. Реальные desktop/mobile screenshots, keyboard/focus проверка и доступные формы по [UX checklist](ux-checklist.md).

Эти пункты пока являются условиями приёмки. Их прохождение должно быть записано в отдельных implementation reviews со свидетельствами.
