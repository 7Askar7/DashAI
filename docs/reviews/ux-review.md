# Независимая UX-проверка работающего Agentboard

Дата: 4 октября 2026 года. Рецензент — отдельный агент UX, не автор frontend. Основание: [исследование UX/UI](../research/03-ux-ui.md), [план проверки](ux-checklist.md), [архитектура](../architecture.md).

## Заключение

На финальном production build `DgQFNpWc` пройдены **42 проверки рабочих сценариев** и **6 отдельных проверок мобильной клавиатуры**. Исправления основных дефектов независимо перепроверены в настоящем Chromium. Создание проекта → разделов → задач, сохранение контекста и причин, ошибки завершения, конфликт двух авторов, повторная отправка после сетевой ошибки, история, экспорт и копирование двух конфигураций работают. Открытых P0/P1/P2 по проверенным сценариям не осталось.

Визуальная оценка: интерфейс выглядит как рабочий инструмент. Проект и его разделы имеют устойчивую иерархию; карточки показывают результат, зачем он нужен и исполнителя; подробности отделяют описание, обоснование, критерии и записи. Графитовая палитра, мятный акцент, последовательные интервалы и текстовые обозначения статусов согласованы. После увеличения основных шрифтов карточки и формы читаются заметно лучше. На 390/320 px доска превращается в список с видимыми статусами, а формы и детали сохраняют все основные действия.

## Среда и границы независимости

Python Playwright из уже установленной `.venv`, headless Chromium `chromium-1234`, настоящий production `dist`. Реальный workspace `http://127.0.0.1:4242` проверялся только чтением. Все создания, PATCH и записи выполнялись на отдельном сервере с произвольным свободным портом и одноразовой директорией `tempfile`; сервером и директорией управляет скрипт. Production-данные не загрязнялись QA-записями. Тестовый сервер запускается скрытым Windows subprocess (`CREATE_NO_WINDOW`).

Viewport: 1440×1000, 390×844, 320×844. Для форм и drawer screenshot показывает viewport; для длинных досок, истории и connectors используется full-page. После navigation учтено завершение CSS-перехода. Содержимое включает длинный русский заголовок, переносы строк в what/why, Windows path с пробелами, произвольный цвет от агента и 14 событий истории.

Проверка не является формальной сертификацией WCAG, исследованием с пользователями либо заявлением о проверке всех screen readers/браузеров. Контраст измерен для видимых текстовых узлов доски с вычисленными непрозрачными фонами; градиенты, placeholders, контуры и все состояния UI этим сканированием не покрыты. Реальное подключение установленного Codex/Claude Code проверяется connector/API review отдельно; здесь проверены UI-инструкции и точный clipboard двух конфигураций.

## Фактически пройденные сценарии

Полный журнал: [ux-results.json](../../artifacts/qa/ux-results.json); воспроизводитель: [ux_workflow.py](../../artifacts/qa/ux_workflow.py).

| Группа | Наблюдавшийся результат |
| --- | --- |
| Пустое пространство и создание | Empty state, первый проект, два раздела, две задачи; reload сохранил их. Native required validation удержала форму и фокус |
| Контекст карточки | Отдельные what, why, acceptance criteria, стабильный AD-ID, исполнитель и хронология доступны в drawer |
| Сетевая ошибка | Принудительно оборван PATCH проекта; ошибка видна, черновик цели сохранён. Retry успешно сохранил тот же черновик |
| Произвольный цвет | Цвет `#aabbcc`, заданный API агентом, виден в форме и сохраняется при редактировании цели человеком |
| Ограничения результата | `done` без критериев отклонён; `done` с критериями без evidence отклонён; после UI-created evidence переход выполнен |
| Зависимости | Попытка начать зависимую задачу до завершения prerequisite отклонена; статус сохранился. Финальный текст «Сначала завершите блокирующие задачи» не требует бесполезного refresh |
| Типы записей | Выбор evidence изменяет поля и сохраняет `kind=evidence`; choice change открывает список файлов и сохраняет его в правке |
| Параллельное редактирование | Второй автор меняет приоритет при открытом черновике названия. Первый save получает конфликт; refresh сохраняет черновик; повторный save изменяет только название и сохраняет чужой `urgent` |
| Поиск и фильтры | AD-ID, пустой результат с clear action, фильтр раздела и Ctrl+K focus работают |
| История и экспорт | Поиск причины находит нужное событие; project JSON действительно скачивается и содержит обе задачи |
| Connectors | До первого запроса показано «Запросов пока нет», отдельно объяснено, что last request не является подтверждением работающего процесса |
| Clipboard | Codex TOML и Claude Code JSON копируются, содержат реальный base URL тестового сервера и agentboard, без открытого токена |
| 390/320 px | Доска, история и connectors без document horizontal overflow; формы и drawer без внутреннего horizontal overflow; footer формы достигается вертикальной прокруткой |
| Browser errors | Не зарегистрировано необработанных page JS errors |

Native `<dialog>` не допускает фокусирования фоновых controls. При обходе Tab Chromium один раз отдаёт фокус browser chrome (`document.hasFocus() === false`, activeElement BODY), затем возвращает его внутрь. Это не было ошибочно засчитано как доступность фона.

## Клавиатура и измерения доступности

Воспроизводитель [ux_keyboard.py](../../artifacts/qa/ux_keyboard.py), результат [ux-keyboard.json](../../artifacts/qa/ux-keyboard.json): закрытая mobile sidebar не получает Tab; открытая удерживает 14 последовательных Tab внутри; main становится inert; Escape закрывает меню; focus возвращается к opener; переход к desktop 1440 px закрывает overlay и снимает inert. Native modal также возвращает focus к исходной кнопке после Escape.

Частичный DOM-скан [ux_accessibility.py](../../artifacts/qa/ux_accessibility.py) / [ux-accessibility.json](../../artifacts/qa/ux-accessibility.json): 132 текстовых образца desktop, 88 на каждой mobile ширине; в измеренной выборке минимальный ratio 6.01:1 desktop и 6.28:1 mobile. В видимых controls не найдены отсутствующие labels/names и targets меньше 24×24 CSS px. Это измерение не заменяет все критерии WCAG, перечисленные в плане.

## Дефекты и перепроверка

| ID / severity | Воспроизведение и наблюдение | Итог |
| --- | --- | --- |
| UX-F01 / P1 | Mobile390, от `.skip-link` нажать Tab. В ранней сборке focus посещал 8 controls закрытой sidebar с `x=-222`, без видимого focus | Исправлено в `2FojN9cV`; независимая клавиатурная проверка PASS, hidden menu больше не попадает в tab order |
| UX-F02 / P1 | Открыть мобильное меню. Focus оставался на opener за overlay; Escape не закрывал меню | Исправлено: focus внутри, background inert, Tab containment, Escape и restore подтверждены отдельным browser сценарием |
| UX-F03 / P2 | Ранний desktop: большинство рабочего текста 8–11 px; mobile «Агенты» height 23.5 px | Исправлено до B9XT9YGA: card title14/body12, inputs12, history12; mobile agents32 px. Новые screenshots и DOM измерения подтверждают изменение |
| UX-F04 / P2 | Открыть edit, другой автор меняет priority, получить conflict и нажать refresh. Сообщение выводило raw `priority, version, updated_at` | Исправлено в `2FojN9cV`: «Другой автор изменил: Приоритет». Служебные version/timestamp отсутствуют; draft и чужой приоритет сохраняются |
| UX-F05 / P2 | Зависимая задача с незавершённым prerequisite → edit → in_progress → save. Ранняя ошибка «Конфликт изменений… Обновите данные перед повторным сохранением» рекомендовала refresh, который не завершит prerequisite | Исправлено в `DgQFNpWc`: «Сначала завершите блокирующие задачи». Независимый повторный browser сценарий PASS; настоящий version conflict по-прежнему сохраняет черновик и правильно предлагает обновить данные |

Входящие регрессии от автора реализации также проверены независимо и закрыты: управляемый note selector сохраняет фактический выбранный kind; custom color не заменяется первым preset; stale edit не переписывает untouched priority. Исправление history race наблюдалось в коде автора, но искусственная перестановка сетевых ответов не включена в эти 42 проверки и не выдаётся за проведённый эксперимент.
