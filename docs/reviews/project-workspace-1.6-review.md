# Независимый review рабочего пространства DashAI 1.6

Проверено 17 октября 2026 года. Область этого прохода: `server/integrations.py`, `server/modules.py`, общие транзакции и маршруты в `server/app.py`, идентичности и конфигурации MCP в `connectors/`. UI и выпуск нативных пакетов проверяются отдельно. Проверки выполнялись на временных базах; личные проекты и credentials не читались и не изменялись.

## Найденные и исправленные ошибки

1. **Отключённая очередь блокировала другие проекты.** Первоначальный worker применял `LIMIT 10` до проверки включённого проекта/подключения. Десять старых приостановленных записей постоянно занимали весь batch: три последовательных запуска обработали ноль документов активного проекта. Теперь SQL исключает отключённые подключения и проектные модули до `LIMIT`; отдельный replay обработал активный проект с первого запуска.
2. **Неопределённый POST терял защиту от дубликатов после выключения модуля.** POST мог создать удалённый документ и потерять ответ. Выключение документа превращало `uncertain` в `removed`, повторное включение изменённого текста — в `pending`. При задержке поискового индекса это создавало второй документ. Состояние `removed_uncertain` сохраняет неопределённость; возвращение документа с прежним или новым текстом сначала проверяет удалённый результат и не повторяет создание вслепую. Для обычного `removed` повторное включение также больше не застревает из-за совпадения digest.
3. **Восстановление после неопределённого POST могло затереть чужую правку.** Первоначальный `recover()` принимал текущую удалённую версию за одобренную исходную. После ручного изменения страницы/задачи автоматический retry выполнял PUT и терял эту правку. `integration_attempts` теперь атомарно сохраняет исходный материал перед отправкой; восстановленный объект сравнивается с исходным отправленным содержимым. Несовпадение оставляет неопределённость и требует явной проверки/перезаписи человеком. Независимый replay сохранил ручную правку в обеих системах и зафиксировал ноль PUT.
4. **Опрос доски загружал полные тексты прошлых редакций модулей.** Даже сокращённый список модулей не устранял до 40 MB текстов в последних 100 audit events. Для `/api/bootstrap` и `/api/projects/{id}` новый `Store.events(summary=True)` исключает только `project_module.before/after.content` на SQL-чтении, до декодирования JSON в Python. Сами строки audit неизменны; `/api/history`, project export и task detail продолжают возвращать полные данные. Все четыре вызова `Store.events` и отдельное чтение истории проверены.

Эти четыре воспроизведённые ошибки устранены в проверенном варианте backend. Их проверки оставлены в `tests/test_integrations.py` и `tests/test_modules.py`.

## Проверенные границы

Настройку внешней отправки, выдачу credentials и явную перезапись выполняет человек. Обычный агент пишет данные через тот же HTTP/domain слой и не создаёт отдельный store. Произвольное имя идентичности независимо от выбранного формата MCP-клиента; оно не запускает модель и не доказывает наличие активной сессии.

Confluence создаёт дочерние страницы закреплённого page ID и проверяет их пространство/родителя перед изменением. Jira создаёт задачи закреплённого числового project ID и проверяет принадлежность существующей задачи перед обновлением. Изменить корень существующего подключения нельзя. Выключение модулей сохраняет локальные документы и удалённые mappings. Локальная правка, её audit и постановка в очередь совершаются в одной SQLite-транзакции.

Секрет интеграции хранится в отдельном локальном файле, создаваемом с приватными POSIX-правами; в DB, audit, project export и обычные read-ответы он не попадает. Конфигурации MCP содержат путь token-файла, а не значение токена. HTTP redirects и наследование proxy окружения для интеграций отключены, TLS проверяется; запрещены loopback, link-local и служебные адреса, приватные HTTPS-адреса разрешены для Data Center. Доверенная граница приложения остаётся одним пользователем ОС.

## Существенные ограничения проверки и API

**Реальный Atlassian tenant не подключался.** Четыре REST-варианта проверены через `httpx.MockTransport`, без настоящих пользовательских токенов и внешних записей. Это проверка контрактов, scope и отказов, а не подтверждение прав конкретной компании, SSO, доступности её сервера или настроек issue screens.

**Jira не предоставляет документированную атомарную проверку версии для этого PUT.** Fingerprint блокирует ручные правки, которые уже видны на предшествующем GET. Изменение или перенос задачи между этим GET и PUT остаётся гонкой внешнего API: локальный lock её не устраняет. Для серверного ограничения назначения используйте отдельную Atlassian-учётную запись с Create/Edit-доступом только к выбранному Jira-проекту; при совместном ручном редактировании предпочтительна проверяемая ручная синхронизация. Не заявляем гарантию отсутствия всех внешних lost updates. Основание: [актуальный Edit issue](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issues/), официальные запросы conditional locking [JRACLOUD-26005](https://jira.atlassian.com/browse/JRACLOUD-26005) и [JRASERVER-26005](https://jira.atlassian.com/browse/JRASERVER-26005), закрытые с решением Won’t Do. Вывод о сохраняющемся окне гонки следует из отсутствия серверного условного изменения в используемом контракте. Confluence передаёт ожидаемый следующий номер версии в PUT.

**Остановка действует перед следующим сетевым запросом.** Она не отзывает уже отправленный HTTP-запрос и не откатывает завершённое удалённое действие. После неопределённого результата сначала выполняется поиск/сверка, а повторное создание требует подтверждения отсутствия человеком.

**Формат публикации — текст и исходники нотаций.** Confluence получает экранированный текст в `pre`, Jira Cloud — текстовые ADF-параграфы. Mermaid переносится как исходник; нативная визуальная отрисовка схем в Atlassian этими тестами и реализацией не заявлена. Удаление локального материала не удаляет удалённую страницу/задачу.
