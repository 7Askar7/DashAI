# Навигация по большой карте проекта

Дата исследования: 17 октября 2026 года. Источники — официальные документация продуктов и WAI-ARIA APG. Это экспертное исследование интерфейсов; интервью с пользователями не проводились.

## Наблюдения из первичных источников

- VS Code сочетает дерево, Quick Open по имени и фильтрацию Explorer. Клавиша Down переводит фокус из поиска к совпадениям; родительские папки сохраняют ориентир. Вывод для DashAI: чтение дерева и быстрый поиск нужны одновременно, особенно при неизвестной структуре. [VS Code: Explorer и Advanced tree navigation](https://code.visualstudio.com/docs/getstarted/userinterface#_explorer-view).
- Sourcegraph разделяет запрос и область поиска, ищет отдельные слова в имени или содержимом, поддерживает ограничение полным путём. Вывод: пользователь должен находить файл по объяснению его назначения; полные пути в результатах различают одинаковые имена. Полный язык запросов для локальной карты избыточен. [Sourcegraph: Search query syntax](https://sourcegraph.com/docs/code-search/queries).
- GitHub соединяет поиск и навигацию по связям, показывает переходы к определениям и references. Вывод: переход из архитектуры или связанных описаний должен раскрывать именно выбранный путь и не зависеть от прежнего фильтра. DashAI использует опубликованные агентом связи, а не заявляет собственный анализ кода. [GitHub: Navigating code](https://docs.github.com/en/repositories/working-with-files/using-files/navigating-code-on-github).
- APG различает фокус и выбранный объект; определяет Arrow Up/Down, Left/Right, Home/End и Enter. Для частично отрисованного дерева позиции, размер набора и уровень задаются явно. Вывод: один вход Tab в дерево, навигация стрелками без открытия каждого описания, Enter для чтения. [WAI-ARIA: Tree View Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/).

## Принятый интерфейс

Карта сохраняет две области: навигация слева и объяснение справа. На широком экране они прокручиваются независимо. Папки изначально свёрнуты; раскрывается только путь выбранного материала. Кнопки «Свернуть все папки» и «Показать выбранный путь» возвращают ориентир без потери открытого описания. Счётчик папки показывает число опубликованных вложенных файлов; это не размер реального репозитория.

Поиск по пути, заголовку, краткому описанию, назначению и шагам работы выводит плоский список с полным путём. Несколько слов должны присутствовать в суммарном тексте файла. Совпадения не требуют вручную раскрывать родителей. Нулевая выдача объясняет, что искать, и позволяет сбросить запрос, сохраняя читаемое описание. Связанный путь сбрасывает фильтр и раскрывает родителей; отсутствующая в снимке ссылка сообщает о необходимости проверить историю.

На узком экране дерево сворачивается после выбора, фокус переходит к заголовку объяснения. Поиск снова открывает навигацию. Строки высотой 48 px обеспечивают читаемую плотность и достаточную область нажатия. Длинные имена сокращаются в списке; полный путь виден в подсказке и в описании.

## Стоимость и ограничения

Индекс путей строится один раз на новый снимок, за время пропорциональное числу сегментов путей; сортируются только дочерние списки. Нет фильтрации всего манифеста в каждом узле и рекурсивного React-дерева. Строится плоский список раскрытых строк; DOM содержит окно видимых строк с небольшим запасом и активный элемент для `aria-activedescendant`. Раскрытие широкой папки не добавляет тысячи кнопок в DOM. Поиск использует заранее собранный текст и линейный проход по опубликованным материалам.

Потолок HTTP-манифеста повышен до 10 000 элементов / 8 MB, сохранённой карты — 12 MB. Для более крупных репозиториев агент публикует обозначенную в `source_revision` область анализа. Превышение отклоняется явно; документация не обрезается молча. Ускорение UI не означает, что DashAI загрузит весь репозиторий автоматически.

Запуск regression: `.venv/Scripts/python.exe scripts/large_project_map_smoke.py`. Скрипт создаёт отдельные SQLite/API и Vite на свободных портах, публикует 2000 настоящих элементов, проверяет выбор последнего файла, клавиши, поиск, раскрытие связанного пути, mobile и отсутствие изменений карты от навигации. Дополнительно 10 000 синтетических элементов подставляются только в браузерный read-ответ для проверки DOM; это не свидетельство поддержки такого объёма публикации API. Результаты и снимки записываются в игнорируемую `artifacts/qa/large-project-map/`.

Проверка 17 октября: browser regression прошёл на 1440, 390 и 320 px. Для 10 000 строк в DOM осталось 22 элемента дерева; поиск занял 313 ms, для настоящего снимка 2000 элементов — 171 ms. Это измерения конкретного локального прогона с учётом Playwright, а не гарантированная задержка. Отдельный настоящий API-тест публикует 10 000 элементов и проверяет сохранение последнего пути (`tests/test_project_map.py`, 2 passed вместе с прежним transactional regression).

Тем же browser regression проверено включение активных документных модулей в preview/HTML/Markdown, исключение отключённого модуля, экранирование HTML, запрет подмешивания текущих модулей в историческую карту и явная ошибка с блокировкой неполного экспорта при недоступном API модулей. После повторной загрузки экспорт восстанавливается.
