# Карта проекта и документация — 1.5.0

В проекте доступны вкладки «Карта проекта», «Архитектура», «Документация». Они работают с опубликованным снимком выбранного проекта в той же SQLite-базе, что задачи и история. Подготовленные материалы в `docs/design/` остаются отдельным прототипом и в пользовательские проекты не подставляются.

## Рабочий процесс

1. Человек нажимает «Задача на анализ». На общей доске появляется настоящая задача типа «Документация». Она ожидает внешнего агента; приложение не запускает модель автоматически.
2. Агент берёт задачу, читает разрешённые исходники в своей среде, исключает секреты, локальные данные, зависимости и результаты сборки.
3. Агент вызывает `get_project_map` и публикует полный манифест области анализа через `publish_project_map`: относительные пути, SHA-256 файлов, объяснения назначения/работы и Mermaid-схемы.
4. Человек читает описания и схемы, сверяет их с исходниками и при необходимости отмечает проверенными с причиной. Публикация агента сама по себе не становится подтверждённой проверкой.
5. Во вкладке документации человек выбирает разделы и схемы, задаёт название/контекст и сохраняет состав с причиной. Markdown, автономный HTML и печатный вид используют выбранные материалы.

В дереве поддерживаются раскрываемые папки и отдельные описания явно опубликованных папок. Код не открывается. Поиск ищет путь, заголовок и объяснение. Архитектура показывает только опубликованные схемы: C4 L1/L2/L3, UML Sequence/State, ERD и Flowchart. Один Mermaid-исходник используется для реальной отрисовки и Markdown; HTML включает отрисованные SVG. Ошибка синтаксиса видна в UI и не уничтожает текст. Перед HTML-экспортом выбранные схемы должны успешно отрисоваться.

Связанный путь под схемой открывает дерево, выбирает соответствующее объяснение и переводит фокус на его заголовок. Настройки документа заблокированы во время сохранения и при просмотре исторической версии; чтение и экспорт истории остаются доступны.

Веб-браузер скачивает документ; VS Code использует системный диалог сохранения через ограниченный host bridge. HTML автономен, без внешних скриптов/ресурсов. PDF сохраняется через печать браузера; для печати вне VS Code можно открыть скачанный HTML. Это локальная сборка документа, не публикация на внешнем сайте.

## Данные и версии

`project_maps` хранит текущую карту проекта, `project_map_revisions` — неизменяемые снимки всех версий. Создание таблиц добавляет функциональность к существующей базе и не переписывает задачи, credentials или их историю. Каждая запись, ревизия и audit event проходят одной транзакцией `Store.write`; `expected_version` и idempotency работают через общий HTTP API. Audit содержит краткие метаданные, полные прошлые материалы доступны по номеру версии и входят в экспорт проекта.

Полный манифест может описывать ограниченную область репозитория; `source_revision` обязан её идентифицировать. Отсутствующий в новом манифесте путь удаляется из текущего дерева и сохраняется в предыдущих ревизиях. Описание без нового текста сохраняется; при изменении собственного hash, связанных исходников или вложенных файлов указанной папки становится `stale`. Схемы без нового исходника также устаревают при изменении связанных путей; схема без списка путей зависит от всего опубликованного снимка. Новый текст имеет статус `draft`. Отметку `reviewed` ставит только человек. Проверка устаревшего текста запрещена до обновления.

Сравниваются опубликованные агентом hashes. Приложение не читает репозиторий и не следит за файловой системой. Поэтому UI всегда показывает ревизию анализа и сообщает, что последующие изменения исходников не проверены. Опубликованный hash является утверждением автора; приложение не выдаёт его за независимую сверку.

## HTTP API

Все write-запросы требуют авторизацию агента либо локальный browser credential, `reason`, `expected_version` (0 для новой карты) и поддерживают `idempotency_key`.

- `GET /api/projects/{id}/map` — текущая карта; `?version=N` — неизменяемая историческая версия.
- `PUT /api/projects/{id}/map` — полный манифест: `{expected_version, source_revision, files, diagrams?, reason, idempotency_key?}`.
- `PATCH /api/projects/{id}/map/document` — `{expected_version, document, reason, idempotency_key?}`.
- `POST /api/projects/{id}/map/review` — `{expected_version, path? | diagram_id?, reason, idempotency_key?}`; ровно одна цель, только человек.
- Обычный экспорт проекта включает `project_map` и `project_map_revisions` наряду с прежними данными.

Файл: `{path, kind: "file" | "directory", sha256, description?}`. Для файла обязателен lowercase SHA-256; для папки hash отсутствует/null. Описание: `{title, summary, purpose, workflow: string[], related_paths: string[]}`. Отсутствующее/null описание сохраняет прежний текст. Связанные пути нового текста должны входить в текущий манифест. Ссылки прежнего текста на удалённые файлы остаются как исторический контекст со статусом `stale`.

Схема: `{id, title, notation, scope, explanation, legend, source, related_paths}`. `notation`: `c4_context`, `c4_containers`, `c4_components`, `sequence`, `state`, `erd`, `flowchart`. C4 использует Mermaid `flowchart` с явными типами/границами. Публикация массива схем заменяет набор; `[]` очищает, отсутствие/null сохраняет предыдущий набор с пересчётом актуальности.

Состав документа: `{title, context, sections, diagram_ids}`. Допустимые разделы: `intro`, `diagrams`, `files`, `decisions`, `verification`. Выбранные схемы должны существовать в карте. Решения из полноценного ADR-хранилища эта версия не моделирует: раздел ссылается на журнал, не придумывая решения из кода.

Манифест ограничен 2000 элементами и 2 MB входных данных; схемы — 100 элементами по 30 000 символов. Превышение возвращает 422 и требует уменьшить область анализа, а не молча обрезать документацию. Относительные пути валидируются; секреты, приватные ключи, локальные данные и результаты сборки исключаются. Новые схемы не принимают действия, init-директивы или внешние ресурсы. Текст выводится как текст. Mermaid работает в strict-режиме; результат изолирован sandbox iframe и CSP без сетевых ресурсов/скриптов. HTML-экспорт также ограничен CSP.

Полная сохраняемая карта, включая оставленные прежние описания и служебные метаданные, ограничена 3 MB: превышение возвращает 422 и откатывает запись вместе с audit. В VS Code один экспортируемый документ ограничен 6 000 000 байт UTF-8 в host bridge. Для более крупного документа уменьшите состав; файл не обрезается молча.

## MCP

`get_project_map(project_id, path?, diagram_id?, version?, offset=0, limit=50)` возвращает краткий пагинируемый манифест; `path` возвращает одно полное описание, `diagram_id` — один полный Mermaid-документ. Read не раскрывает credentials. `publish_project_map` принимает те же типизированные поля, что HTTP, и только перенаправляет запрос. Коннектор не читает исходники и не открывает SQLite.

Перед публикацией агент перечитывает текущую версию. После 409 он читает карту повторно и подтверждает намерение заново, не перезаписывая чужие данные. После сетевого сбоя повторяет тот же payload и idempotency key. Создание новой карточки, публикация карты и завершение задачи — отдельные осмысленные операции; evidence задачи должно содержать реально выполненную проверку.

## Проверки и границы

`tests/test_project_map.py` проверяет persistence/restart, версии, конкурентный CAS, идемпотентность, атомарный откат при сбое аудита, ограничения путей/схем, человеческую проверку, устаревание зависимостей и экспорт истории. Настоящие MCP-сессии проверяют публикацию Codex и чтение Claude через общий API; frozen smoke повторяет путь на собранных EXE. Browser smoke проходит исходный Kanban и новый сценарий карты на изолированной базе, включая семь реальных Mermaid-отрисовок, композицию/экспорт, конфликт, reload и mobile reflow.

Это готовый путь публикации и чтения результатов внешнего агента. Автоматический фоновый запуск агентов, watcher репозитория и независимое доказательство истинности ИИ-текста не реализованы и не заявляются.
